Lecture 1 · Indexing

Access paths and index trade-offs

An index helps locate records; whether it helps depends on file order, index density, and how many records the query will fetch.

  • Dense: an entry for each search-key value/record; supports direct membership checks.
  • Sparse: fewer entries, typically anchors in an ordered data file; search the indicated data block afterward.
  • One physical ordering supports one primary/clustering access path; secondary indexes provide other paths at extra update cost.
  • A B-tree keeps keys ordered: extremes are at the leftmost/rightmost leaf.
Review the full indexing guide

Lecture 2 · Query processing

Translate, transform, then execute

The DBMS turns a declarative SQL request into an executable plan. Logical equivalence does not imply equal execution cost.

  • A query block is one SELECT-FROM-WHERE expression.
  • Selection filters rows; projection removes columns (and may remove duplicates).
  • Push selection early to reduce rows; push projection early to narrow rows, but retain needed columns.
  • Selections can use different access paths; a secondary index is not automatically cheaper than a scan.
Review the full query-processing guide

Lecture 3 · Joins and aggregates

Choose the method for the available data

Join cost depends on relation sizes, buffer space, ordering, and indexes—not just the names of the algorithms.

  • Nested-loop join repeats inner work; block nested-loop join uses buffers to read outer chunks.
  • Single-loop join probes an index on the inner relation for each outer tuple.
  • Sort-merge join advances through ordered inputs and handles matching key groups.
  • Grouping benefits when equal grouping values are adjacent; aggregates such as SUM still need the values being summed.
Review the full joins and aggregates guide

Lecture 4 · Optimization

Reduce work, then estimate the remaining work

Heuristics improve a logical plan; cost estimates help choose among plausible physical plans.

  • Push restrictive selections toward base relations; replace product-plus-equality-selection with a join.
  • Push projections down only after retaining output, filter, and join attributes.
  • Catalog statistics describe relations and indexes; histograms capture non-uniform value distributions.
  • Choose an index only when its expected I/O is better than scanning the data.

Formula desk

Write down what each symbol means, substitute values, and show rounding. These are the recurring calculations across the lecture guides.

Records per block

bfr = ⌊ block size ÷ record size ⌋

Round down: a partial record cannot fit in a block.

Blocks for a file

b = ⌈ number of records ÷ bfr ⌉

Round up: a partly filled final block still uses one block.

Block nested-loop join

b_outer + ⌈ b_outer ÷ (M − 2) ⌉ × b_inner

M is the available buffer count; reserve buffers for the inner input and output.

Join-result estimate

|R ⋈ S| ≈ Js × |R| × |S|

In these lecture notes, Js is the fraction of Cartesian-product pairs that satisfy the join condition.

Exam habit: Write the formula first, state your outer/inner choice, substitute, then explain why the chosen plan is appropriate. Keep logical rewrites separate from physical I/O cost.

Worked example · file blocks

  1. Block size = 4,096 bytes; record size = 100 bytes.
  2. bfr = ⌊4096 ÷ 100⌋ = 40 records per block.
  3. For 50,000 records, b = ⌈50000 ÷ 40⌉ = 1,250 blocks.

Use a floor for records that must fit wholly inside a block, then a ceiling for however many blocks the file needs.

Worked example · block nested-loop cost

  1. Let the outer be 40 blocks, the inner 100 blocks, with 6 buffers.
  2. Outer blocks per chunk = M − 2 = 4; passes = ⌈40 ÷ 4⌉ = 10.
  3. Cost = 40 + 10 × 100 = 1,040 block reads.

Switching the outer to 100 blocks gives 100 + ⌈100 ÷ 4⌉ × 40 = 1,100, so the 40-block outer is cheaper here.

Worked example · safe projection pushdown

For SELECT E.Name FROM Employee E JOIN Department D ON E.Dno=D.Dno WHERE D.Location='North', selections and projections can be pushed toward the inputs.

  1. Filter Department on Location='North'.
  2. Keep Dno in both inputs until the join is complete.
  3. Keep Name from Employee; project the final result to Name after the join.

Projecting away Dno too early would make the join impossible.

Worked example · estimate a join result

If |R|=500, |S|=200, and Js=0.02, the Cartesian product contains 500 × 200 = 100,000 pairs.

  1. Apply the estimated matching fraction: 0.02 × 100000.
  2. The estimated join result has 2,000 tuples.

This estimates cardinality; it is not itself a disk-I/O cost. A cost calculation also needs a physical algorithm and block counts.

Questions 1-27

Indexing

01

Indexing · calculation

Blocks are 4,096 bytes and records are 100 bytes. How many records fit in one block under the fixed-length model?
Show explanation

Correct: 40. Compute ⌊4096 ÷ 100⌋ = ⌊40.96⌋ = 40. Round down because the record count per block must be a whole number; the leftover bytes are unused in this model.

02

Indexing · structure

When is a sparse index appropriate in the usual file-organization model?
Show explanation

Correct: C. Sparse entries work as block anchors because the ordered data file lets the DBMS locate the range where a key belongs, then search that block. With an unordered heap file, a missing key could be anywhere, so block anchors do not suffice.

03

Indexing · trade-offs

Which index type can a table have multiple instances of, on different search fields?
Show explanation

Correct: D. A file has one physical order at a time, so it cannot be simultaneously ordered by many different primary or clustering fields. Secondary indexes add alternate access paths, with extra storage and maintenance on inserts, deletes, and updates.

04

Indexing · terminology

Dense and sparse describe which property of an index?
Show explanation

Correct: B. Dense/sparse describes index-entry coverage: dense indexes have an entry for each search-key value or record (depending on the model); sparse indexes store fewer entries, often one per data block. It is not the same classification as primary, clustering, or secondary.

05

Indexing · B-tree

For a B-tree index on an ordered attribute, where is the maximum key found?
Show explanation

Correct: A. B-tree leaf entries are kept in key order. Following the rightmost child pointers reaches the largest key; the analogous leftmost path finds the minimum.

06

Indexing · use case

A query groups many employee rows by Dno. Which index is most directly helpful for bringing equal department values together?
Show explanation

Correct: C. A clustering index orders the data file by a non-unique field, placing rows with equal Dno values together. The DBMS can process groups as it scans rather than first sorting all rows by department.

07

Indexing · file-size calculation

A file has 50,000 records and a blocking factor of 40. How many blocks are needed?
Show explanation

Correct: B, 1,250 blocks. Divide records by records per block: 50000 ÷ 40 = 1250. In general use the ceiling, ⌈r/bfr⌉, because a partly filled final block still occupies a block; this example divides evenly.

08

Indexing · unsuccessful search

If the index is in memory and unsuccessful searches are common, what benefit can a dense index offer over a sparse index?
Show explanation

Correct: D. A complete dense index can establish that a search key is absent without fetching a data page. A sparse index only gives nearby anchors; the candidate data block may need to be read to decide that the key is missing. This speed benefit uses more index entries/storage.

09

Indexing · index categories

Which statement correctly distinguishes primary and clustering indexes in the lecture's file-organization model?
Show explanation

Correct: A. Both describe the file's physical ordering and index relationship. A primary index is associated with ordering on a key; a clustering index orders records on a non-key field, so records with equal values form groups. Dense/sparse is a separate coverage property.

10

Indexing · selectivity

A secondary index identifies 8,000 matching records scattered across most blocks. Which conclusion is safest?
Show explanation

Correct: C. The index access cost includes fetching data pages, not only traversing index levels. A non-clustering index can lead to many random reads. The optimizer compares total estimated I/O for the index plan against a sequential scan; there is no universal qualifying-row threshold.

11

Indexing · aggregate lookup

For a B-tree index on Salary, what is the natural index traversal to find MIN(Salary)?
Show explanation

Correct: B. The leaves are in search-key order, so the first (leftmost) leaf contains the minimum key. MAX uses the corresponding rightmost path. This shortcut depends on an ordered index over the aggregate attribute.

12

Indexing · maintenance

Why does adding several secondary indexes make updates more expensive?
Show explanation

Correct: D. An index speeds some reads but must stay synchronized with the base data. Inserts, deletes, and updates to indexed values can modify multiple index structures, adding work and storage. Index selection is therefore a read/write trade-off.

Questions 28-54

Query processing

13

Query processing · pipeline

Which sequence best describes how a declarative SQL query becomes a result?
Show explanation

Correct: D. The DBMS first checks and translates the declarative request into a logical form (often relational algebra), transforms equivalent expressions, then selects physical operators and executes the plan. Optimization happens before execution.

14

Query processing · definitions

A query block is a single SELECT-FROM-WHERE expression.
Show explanation

Correct: A. A query block is the basic SELECT-FROM-WHERE unit. A complex SQL statement may contain several blocks because of nested subqueries, but GROUP BY is not required for a block.

15

Query processing · projection

Pushing a projection closer to a base relation most directly reduces the size of intermediate tuples by reducing:
Show explanation

Correct: C. Projection retains selected attributes, making intermediate tuples narrower and potentially reducing I/O. It does not generally filter rows; selection does that. Keep every attribute needed later for output, filtering, or joining.

16

Query processing · equivalence

When can σ (selection) and π (projection) be reordered without changing the result?
Show explanation

Correct: B. A selection cannot test a column that an earlier projection has discarded. For example, project Name, Salary before selecting on Salary is valid; project only Name first and the salary predicate can no longer be evaluated.

17

Query processing · access paths

A non-key secondary index matches a large fraction of a table, and matching rows are scattered across data blocks. Which plan is often cheaper?
Show explanation

Correct: D, often. Many secondary-index hits can cause many random data-block reads. If much of the file qualifies, a sequential scan may do less I/O. The optimizer compares estimated costs; this is a rule of thumb, not an unconditional law.

18

Query processing · conditions

A predicate is P OR Q, but there is no useful access path for Q. Why may using only an index for P be incorrect?
Show explanation

Correct: A. OR includes rows matching either branch. Reading only the P index omits rows that match Q alone. An index plan needs a way to cover both branches (for example, suitable indexes combined correctly); otherwise a scan may be required.

19

Query processing · selection vs projection

Which relational algebra operator filters rows that satisfy a predicate such as Salary > 5000?
Show explanation

Correct: C, selection. Selection chooses tuples (rows) satisfying a condition. Projection chooses attributes (columns). Remember: selection changes which rows remain; projection changes which fields are carried forward.

20

Query processing · commutativity

Can two selections on the same relation be reordered or combined?
Show explanation

Correct: A. Applying both predicates leaves exactly the rows satisfying both, regardless of which test is evaluated first. The optimizer may reorder them to evaluate a more selective or cheaper condition earlier, while preserving the AND semantics.

21

Query processing · binary search

Which condition is required for the lecture's binary-search selection algorithm on a data file?
Show explanation

Correct: D. Binary search can discard half of the remaining search range only when the file is ordered on the search field. On an unordered heap, a target (or proof that it is absent) could require inspecting the whole file.

22

Query processing · DISTINCT

Why can projecting a column with DISTINCT cost more than a plain projection?
Show explanation

Correct: B. A plain projection can stream attributes from each tuple. To implement set-style duplicate elimination, the DBMS must identify equal projected tuples, commonly by sorting or hashing. If the projected value is already known unique, that extra work may be unnecessary.

23

Query processing · selection estimate

A relation contains 20,000 tuples. A predicate has estimated selectivity 0.05. About how many tuples are expected to qualify?
Show explanation

Correct: C, about 1,000 tuples. Estimated result cardinality is input cardinality times selectivity: 20000 × 0.05 = 1000. Selectivity is a fraction of qualifying tuples; it is not the number of blocks or the I/O cost.

24

Query processing · set operations

Which set operation is not commutative?
Show explanation

Correct: A. Union and intersection do not depend on operand order. Difference does: if R={1,2} and S={2,3}, then R−S={1} while S−R={3}.

Questions 55-81

Joins and grouping

25

Joins · selectivity

If |R| = 100, |S| = 40, and the estimated join result has 1,200 tuples, what is join selectivity Js under the lecture definition?
Show explanation

Correct: C, 0.30. The Cartesian product has 100 × 40 = 4,000 tuple pairs. Thus Js = 1,200 ÷ 4,000 = 0.30: roughly 30% of pairs satisfy the join condition.

26

Joins · block nested loop

A block nested-loop join has bouter=18, binner=60, and M=5 buffers. Ignoring result writes, what is the estimated I/O cost?
Show explanation

Correct: B, 378. The outer chunk holds M−2 = 3 blocks, so there are ⌈18÷3⌉ = 6 passes over the inner relation. Cost is 18 + 6×60 = 378. Show the ceiling and the buffer roles in a written solution.

27

Joins · single-loop join

For a single-loop join that probes an index for each outer tuple, where must the join-attribute index be?
Show explanation

Correct: A. The algorithm reads an outer tuple, then uses its join value to search the inner relation. Therefore the useful index is on the inner join attribute. Choosing a smaller outer input can reduce the number of probes.

28

Joins · algorithm choice

Which conditions are especially useful for a sort-merge join?
Show explanation

Correct: D. Sort-merge scans ordered inputs and advances the pointers according to key comparisons. Existing order avoids sorting cost; otherwise include the cost of sorting both relations before comparing total plan costs.

29

Joins · duplicate keys

R has sorted join keys {1, 3, 5} and S has {3, 3, 6}. Under bag semantics, how many joined pairs have key 3?
Show explanation

Correct: B, two pairs. There is one R tuple with key 3 and two S tuples with key 3, so that group produces 1×2 = 2 pairs. A merge join must process the matching key group, not stop after the first equal value.

30

Grouping · access paths

Why can a clustering index on a GROUP BY attribute help?
Show explanation

Correct: C. A clustering order places rows with the same grouping value together, so groups can be processed sequentially. The rows still have to be read to compute aggregates such as SUM or AVG.

31

Joins · choose the outer input

For a block nested-loop join, bR=40, bS=100, and M=6. Which orientation has lower estimated I/O?
Show explanation

Correct: B. With 6 buffers, the outer chunk holds M−2=4 blocks. R as outer needs ⌈40/4⌉=10 inner scans, costing 40+10×100=1,040. S as outer costs 100+25×40=1,100. Compare the formulas; “smaller outer” is a useful guide, not a substitute for calculating.

32

Joins · block counts

A relation has 1,000 records, each 200 bytes. Blocks are 1,000 bytes. Under the fixed-length model, how many data blocks are needed?
Show explanation

Correct: D, 200 blocks. First compute bfr=⌊1000/200⌋=5 records per block. Then b=⌈1000/5⌉=200 blocks. Do not divide record count by record size directly; first find the blocking factor.

33

Joins · output size

If Js=1 under the lecture's definition |R⋈S| / |R×S|, what does that indicate?
Show explanation

Correct: A. A selectivity of 1 means the result size equals the full product under this definition. It describes result cardinality only; it says nothing about sort order, buffer capacity, or which algorithm will be cheapest.

34

Joins · single-loop join

R has 100 tuples and S has 10,000 tuples. A suitable index exists on S's join field. Which is the natural outer input for an indexed single-loop join?
Show explanation

Correct: C. Scan the smaller R as outer and use each of its 100 join values to probe S's index. The index must be on the inner relation being searched. The estimated cost still depends on index height, matches per key, and data-page locality.

35

Joins · equality conditions

Why can a condition like R.deptId = S.deptId be implemented by a sort-merge join?
Show explanation

Correct: B. With both inputs ordered by the join field, compare the current keys. Advance the pointer with the smaller key; when keys match, output all matching tuples in the equal-key groups before advancing. If inputs are not already sorted, include sorting cost.

36

Aggregates · index coverage

Can a B-tree on Salary return SUM(Salary) by reading only the index?
Show explanation

Correct: D. A covering index containing every required value may avoid fetching data rows, but SUM still needs to combine the values across the relevant leaf entries. A leftmost/rightmost traversal can find MIN/MAX more directly; it does not provide a SUM at a single node.

Questions 82-108

Heuristic and cost-based optimization

37

Optimization · selection pushdown

Why is a selective predicate usually pushed close to its base relation before a join?
Show explanation

Correct: B. Filtering early often means fewer tuples must be joined, sorted, or written as intermediates. It is a useful heuristic, while the optimizer still has to ensure the rewritten plan is equivalent and estimate actual costs.

38

Optimization · projection pushdown

When pushing projections toward base relations, which columns must be retained?
Show explanation

Correct: D. Narrow tuples as early as possible, but do not discard an attribute before its final use. Join keys and predicate attributes may not appear in the final SELECT list and are still essential to the plan.

39

Optimization · statistics

What is a histogram especially useful for when estimating a predicate's selectivity?
Show explanation

Correct: A. If some values occur much more often than others, assuming a uniform distribution can badly misestimate result size. Histograms summarize value frequencies or ranges to improve selectivity and cost estimates.

40

Optimization · catalog

Which information can catalog statistics provide to a cost-based optimizer?
Show explanation

Correct: C. Tuple counts, block counts, tuple widths, index properties, and value-distribution summaries help estimate cardinality and I/O. Statistics may become stale, so estimates are not guarantees.

41

Optimization · plan comparison

A non-clustering secondary index would fetch about 60% of a table's rows from scattered blocks. Which statement is the best cost-based conclusion?
Show explanation

Correct: B, may be. A non-clustering index can lead to many random data-block reads when many rows qualify. A sequential scan may be cheaper, but compare estimated I/O for the actual relation, index, selectivity, and storage costs rather than using a fixed percentage rule.

42

Optimization · strategy

What is the complementary role of heuristic and cost-based optimization?
Show explanation

Correct: D. Heuristic transformations, such as pushing selections down, can reduce obviously wasteful work. Cost-based optimization uses statistics and cost models to compare physical plans that remain. The techniques complement one another.

43

Optimization · product to join

A query has R × S followed by a selection R.id = S.id. What equivalent operator is usually preferable?
Show explanation

Correct: B. The equality selection keeps only matching pairs from the Cartesian product. An equijoin represents that operation directly and lets the physical optimizer choose a join algorithm without materializing the enormous unfiltered product.

44

Optimization · projection safety

A query outputs only E.Name but joins Employee and Department using E.Dno = D.Dno. May Dno be projected away before the join?
Show explanation

Correct: A. The join operator needs both copies of Dno to compare tuples. Push projections down to keep only necessary columns, but include join keys and any columns needed by later predicates. Drop Dno after its final use.

45

Optimization · join cardinality

If |R|=500, |S|=200, and Js=0.02, estimate the number of tuples in the join.
Show explanation

Correct: C, 2,000 tuples. The product contains 500×200=100,000 pairs. Apply the satisfying fraction: 0.02×100,000=2,000. This is a result-cardinality estimate, not the number of block accesses.

46

Optimization · statistics

Two predicates have the same estimated selectivity, but one uses a histogram that shows most values are concentrated in a small range. Why does that histogram matter?
Show explanation

Correct: D. A uniformity assumption treats values as evenly distributed and can be wrong for skewed data. Histogram buckets summarize frequencies/ranges and help the optimizer predict how many rows a particular predicate will retain.

47

Optimization · selection pushdown

For Employee ⋈ Department with a filter Department.Location='North', where can that filter be applied?
Show explanation

Correct: B. Since the predicate refers only to Department, first keep only North departments, then join those with employees. This reduces the input to the join. The rewrite is valid because it does not depend on Employee attributes.

48

Optimization · compare plans

A heuristic rewrite reduces intermediate rows, but a different physical plan has a useful index and better estimated I/O. What should the optimizer do?
Show explanation

Correct: A. Heuristics are useful transformations that often expose better plans, but physical choices depend on statistics, indexes, relation sizes, and I/O costs. Cost-based optimization compares alternatives that preserve query semantics; estimates guide the decision.
